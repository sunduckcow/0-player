# API движка 0-player

Содержание: границы слоёв; контракт игры; правила и случайность; ИИ; Canvas; управление; Session; проигрыш и перемотка; ограничения.

Документ описывает текущую реализацию, а не будущие возможности. Все пути ниже относительно корня 0-player. Сверяй точные сигнатуры с `src/engine/types.ts` и `src/engine/session.ts` перед изменениями.

## Слои и поток данных

| Слой | Файлы | Ответственность |
| --- | --- | --- |
| Движок | `src/engine/types.ts`, `session.ts` | Контракт, фиксированные тики, владение управлением, скорость, очередь, рестарт, история и спасение |
| Общие помощники | `engine/input.ts`, `random.ts`, `draw.ts`, `feedback.ts` | Привязки клавиш, PRNG, палитра/Canvas, эффект проигрыша |
| Игра | `games/<id>/game.ts` | Состояние и правила |
| Автопилот | `games/<id>/ai.ts` | Выбор следующего действия |
| Визуал | `games/<id>/render.ts` | Рисование состояния и эффектов |
| Картридж | `games/<id>/index.ts` | Сборка функций, управление, метрики и параметры восстановления |
| Каталог | `src/catalog.ts` | Регистрация картриджа и создание Session |
| Оболочка | `main.ts`, `storage.ts`, `panels.ts`, `control-layout.ts`, `game-library.ts`, `library-navigation.ts` | DOM, цикл кадров, URL, сохранения, библиотека, диалоги и подсказки |
| Настройки | `settings-ui.tsx`, `appearance.ts`, `components/ui/`, `ui.css` | General и текущая игра; темы/акценты, формы Snake и Tetris |

На игровом тике Session выбирает `game.ai(state)` или элемент ручной очереди и вызывает `game.update(state, action, mode)`. Каталог передаёт состояние в `game.render(ctx, state, frame)` на браузерных кадрах. Рисование не управляет симуляцией. Диалоги и скрытая вкладка приостанавливают игру на уровне оболочки.

## Полный контракт картриджа

```ts
type Action = "up" | "down" | "left" | "right" | "primary" | "secondary";
type Mode = "auto" | "human";
interface GameState { score: number; over: boolean }
interface Metric { label: string; value: string | number }
interface BoardLabel { text: string; x: number; y: number; size?: number }
interface GameControl {
  action: Action;
  keys: readonly string[];
  label: string;
  touch?: string;
  group?: string; // одинаковая метка объединяет действия в один блок подсказок
}
interface RenderFrame {
  time: number;
  mode: Mode;
  paused: boolean;
  recovery?: { progress: number; steps: number };
}
interface Game<S extends GameState> {
  id: string;
  title: string;
  description: string;
  strategy: string;
  controls: readonly GameControl[];
  width: number;
  height: number;
  tickMs: number;
  labels?: readonly BoardLabel[];
  recovery?: {
    steps: number;
    durationMs?: number;
    isLoss?: (state: S) => boolean;
    canResume?: (state: S) => boolean;
  };
  create(seed: number): S;
  update(state: S, action: Action | null, mode?: Mode): S;
  ai(state: S): Action | null;
  render(ctx: CanvasRenderingContext2D, state: S, frame: RenderFrame): void;
  metrics(state: S): Metric[];
}
```

`id` — стабильный уникальный идентификатор для каталога, URL, сохранения и рекорда. `description` описывает игру, `strategy` — поведение автопилота. `width`/`height` — положительные размеры логического Canvas в пикселях, не CSS-размеры и не обязательно размер сетки. `tickMs` — положительный конечный интервал симуляции. Оболочка масштабирует Canvas с сохранением пропорций и отключает сглаживание изображения.

`metrics()` возвращает лёгкие для вычисления данные. Сейчас HUD показывает только первые две метрики; счёт и рекорд выводятся отдельно. В `Game` нет обязательного `rng`, `won`, настройки поля или отдельного результата матча, но текущий загрузчик сохранений требует `rng` и неотрицательный целый `score`. Для победы можно добавить собственный `won` и различать её через `recovery.isLoss`.

## Правила, состояние, время и случайность

- `create(seed)` создаёт новую партию. Session приводит seed к uint32. Храни RNG, таймеры правил, позиции, скорости и фазу партии в состоянии; не в замыкании модуля.
- `update(state, action, mode?)` возвращает новое состояние без мутации входного. Для неизменившихся данных допустимо структурное разделение; изменяемые вложенные массивы сначала копируются. `null` означает отсутствие команды, а не обязательную остановку движения: это определяют правила игры.
- Одни seed, параметры, действия и последовательность режимов должны давать один результат. Переданный `mode` позволяет менять естественную гравитацию/темп человека без задержки ввода. Tetris по умолчанию использует `"auto"` при прямом вызове `update(state, action)`; новую игру тоже проектируй так, чтобы симулятор ИИ без третьего аргумента работал в авторежиме.
- Терминальный `state.over` останавливает обычные тики. Не запускай собственный рестарт из правил или renderer. Победа/проигрыш/новая партия — разные понятия; что считается `over`, определяет игра.
- `random(seed): [value, nextSeed]` из `engine/random.ts` даёт `value` в `[0, 1)` и следующий uint32 seed. Обновляй `state.rng` только при реальных случайных событиях. `Math.random()`, дата, кадры и внешние запросы не входят в воспроизводимые правила.
- Отдельная функция `nextSeed(seed)` перемешивает seed между партиями: соседние значения LCG дают похожие первые результаты. Обычный restart, ручной retry и автоматическая новая партия используют её; `restart(seed)` явно повторяет выбранный seed. Успешная перемотка сохраняет seed и восстанавливает RNG из истории.
- Для физики можно хранить дробные координаты и фиксированный шаг; delta time в `update` не передаётся. Если выбранный тик слишком большой для быстрых столкновений, реализуй ограниченные подшаги внутри правил или выбери подходящий `tickMs`.

## Автопилот

`ai(state)` возвращает один из шести Action либо `null`. Он не изменяет ни состояние, ни доску, не вызывает Session и не перемещает фигуры напрямую. Поиск может симулировать чистый `update` на временных состояниях, но его результатом остаётся обычная команда. Ограничивай объём поиска, чтобы 4× и проверка восстановления не блокировали главный поток браузера. Одного ограничения числа узлов недостаточно: учитывай стоимость проверки целей, повторных симуляций длинных путей и обходов предков. Проверяй отдельно трудные сохранённые состояния и длительные партии, включая почти заполненные поля с изолированными свободными клетками.

После ручной игры или restore нельзя предполагать прежний план, положение на цикле или содержимое кэша. Решение должно воспроизводиться на `JSON.parse(JSON.stringify(state))`. Если фазе ИИ нужен возраст фигуры, храни возраст как часть состояния правил, как `pieceAge` в Tetris. Для случайного выбора одинаково хороших ходов используй детерминированную функцию состояния, не расходующую скрытый RNG.

Реальные примеры: `snake/ai.ts` содержит Explorer и Safe loop, `snake/pursuit.ts` — ограниченный поиск через освобождаемые телом клетки. `tetris/ai.ts` ищет достижимые расстановки, поворачивает и двигает фигуру, затем ускоряет падение. Мгновенный hard drop тетриса остаётся действием игрока.

## Canvas и эффекты

`render` получает логический Canvas, неизменяемое состояние и `frame`. `frame.time` — время браузерного кадра в мс для оформления; не игровое время для правил. `frame.mode`/`paused`/`recovery` позволяют визуально показать текущую фазу.

`clear(ctx,width,height)` закрашивает фон палитрой, `grid(ctx,x,y,cols,rows,cell)` рисует точки сетки. `palette` содержит background, grid, accent, body, text, muted, food, ghost. Это помощники, а не обязательная геометрия новой игры. Изолируй `globalAlpha`, transform и clipping через `ctx.save()`/`restore()`.

Допустим локальный визуальный кэш, например `WeakMap` по контексту Canvas для 120мс вспышки рядов Tetris. Он должен корректно сбрасываться при restore, рестарте и перемотке; без него правила и ИИ дают тот же результат. `recoveryIntensity(frame)` даёт множитель яркости проигрыша, а цвет и затронутую геометрию выбирает игра.

## Управление

```ts
controls: [
  { action: "left", keys: ["ArrowLeft", "h"], label: "Move left", touch: "←" },
  { action: "up", keys: ["ArrowUp", "x"], label: "Rotate", touch: "↑" },
  { action: "primary", keys: ["Enter"], label: "Drop", touch: "Drop" },
]
```

`keys` действительно назначает действия, `label` попадает в подсказки и доступные имена, `touch` включает сенсорную кнопку. Без `touch` действие остаётся клавиатурным и доступным через подсказку. Необязательный group объединяет связанные действия в один блок подсказок (например, четыре направления Snake с group: "Move"), показывая общий набор клавиш и название группы вместо отдельных кнопок. Доступное имя группы сохраняет точные соответствия клавиш действиям; сенсорные кнопки остаются отдельными. На назначения клавиш и touch он не влияет. Один массив создаёт modal/inline/focus-подсказки и touch-панель; дополнительных слушателей игры для этих же кнопок не нужно.

| Системная клавиша | Действие оболочки |
| --- | --- |
| A / физическая Ф | Вернуть автопилот на текущее поле |
| Пробел / P | Пауза / продолжение |
| R | Новая партия с новым перемешанным seed |
| F | Focus и попытка native fullscreen |
| G | Библиотека игр |
| / или ? | Подсказки управления |
| 1–9 | Выбор игры с этим номером каталога |
| Escape | Закрыть диалог или покинуть focus |
| Enter | Настроенное действие; иначе `primary`; после обычного ручного проигрыша запускает новую попытку |

Системные команды имеют приоритет над игровыми. Буквы нормализуются по `KeyboardEvent.code`, есть русская раскладка и fallback по символам. Используй латинские aliases в конфигурации, не дублируй русские. Ввод в полях, IME и комбинации Ctrl/Alt/Meta остаются нативными. Enter на кнопках сохраняет нативную активацию; пробел на кнопке открытого диалога тоже нативный, а на toolbar переключает паузу.

Важное ограничение: key-repeat сейчас разрешён только для `left`, `right`, `down`; повтор `up`, `primary`, `secondary` подавляется. Touch-кнопки посылают одиночные click, без held-state и release. Например, для Pong нельзя предположить симметричное удержание Up/Down. Либо проектируй явные дискретные команды/устойчивое движение по состоянию, либо меняй общий ввод с тестами и обновлением этого API.

## Session: публичный интерфейс

| Метод/свойство | Поведение |
| --- | --- |
| `new Session(game,seed)` | Создаёт состояние через `create`, режим auto, скорость 1, round 1 |
| `state`, `mode`, `paused`, `autoSpeed`, `round`, `seed` | Текущее состояние и параметры; используй методы перехода, не меняй их из правил |
| `speed` | В human всегда 1; в auto — `autoSpeed` |
| `input(action)` | Перехватывает управление, затем ставит команду в очередь до четырёх элементов. Во время паузы не ставит команду и не снимает паузу. Во время восстановления игнорируется |
| `takeControl()` | Переводит в human без сброса поля; сбрасывает часы/очередь и бюджет спасений при переходе из auto. Во время восстановления игнорируется |
| `automate(smooth=false)` | Переводит в auto, очищает очередь; сохраняет поле и паузу, возвращает прежний `autoSpeed`. При true браузер плавно возвращает темп от 1× |
| `togglePause()` | Меняет паузу, очищает накопленное время и очередь |
| `setSpeed(n,smooth=false)` | Принимает только 0.5, 1, 2, 4. По умолчанию меняет темп сразу и сбрасывает часы/очередь; true сохраняет фазу тика и меняет браузерный темп по ease-in-out за 350мс |
| `playbackSpeed` | Текущий промежуточный темп браузера. В snapshot остаются дискретные speed/autoSpeed; промежуточное значение не сохраняется. Оболочка хранит единый множитель в 0-player:speed; URL скорость не содержит |
| `resetClock()` | Очищает накопленное время и ввод; не отменяет восстановление |
| `restart(seed=nextSeed(this.seed))` | Новое поле, round+1, пауза снята, история и восстановление очищены; режим и скорость ИИ сохраняются; явный seed позволяет повторить партию |
| `advance(delta,animateRecovery=true)` | Принимает положительное конечное время в мс; выполняет тики или фазу восстановления. Пауза блокирует оба |
| `advanceFrame(delta,animateRecovery=true)` | Вариант для браузерного кадра: максимум один обычный тик; лишние накопленные целые тики отбрасываются, дробный остаток сохраняется. Таймеры завершения и восстановления получают всё время delta |
| `snapshot()` | Снимок состояния и параметров для сохранения, включая безопасное назначение во время отката |
| `restore(snapshot)` | Принимает уже проверенный снимок; восстанавливает параметры и очищает очередь, часы, историю и восстановление |
| `recovering` | Сейчас идёт спасение/перемотка |
| `recoveryFrame()` | `{progress,steps}` либо undefined; используется каталогом при рисовании |

Шаг симуляции равен `game.tickMs / session.speed`. За один `advance` накопление ограничено восемью тиками; каждое действие потребляется не более одного раза. Браузерная оболочка использует `advanceFrame`, чтобы после дорогого решения ИИ не выполнять цепочку догоняющих вычислений в том же кадре. При нормальной частоте кадров дробное время сохраняет выбранный темп; при перегрузке симуляция замедляется и даёт интерфейсу обработать ввод. В auto ручная очередь не используется. Оболочка не вызывает advanceFrame для скрытого документа и сбрасывает часы при скрытии/возврате и blur.

Оболочка отдельно снимает паузу при клике на игровую подсказку, но обычное клавиатурное `Session.input()` её не снимает. Диалоги сохраняют исходную паузу и возвращают её при закрытии. Для прямых симуляций без DOM можно использовать Session или вызывать `create → ai → update` самостоятельно.

Браузер интегрирует плавную скорость в игровое время; `advance()` для прямых симуляций переключает её мгновенно. `advanceFrame(delta,false)` отключает и easing, и анимацию отката для reduced motion. Пауза замораживает переход; restore/restart отменяют его. Ручной перехват сразу даёт 1×, независимо от easing.

## Проигрыш, восстановление и видимый откат

`recovery` опционален. Без него ручной проигрыш ждёт Enter/R, а auto перезапускает партию через 1500мс с `nextSeed(seed)`. Победа может иметь то же `over=true`, поэтому ей нужен фильтр `isLoss`. Если фильтр отвергает победу, действует обычное терминальное поведение: human ждёт, auto всё равно начнёт новую партию через 1500мс. Фильтр запрещает спасение, а не автоматический рестарт; для бессрочного показа победы потребуется отдельное согласованное поведение.

```ts
recovery: {
  steps: 8,
  durationMs: 640,
  isLoss: state => state.over && !state.won,
  canResume: state => canContinue(state, ai, update, 16, next => next.won),
}
```

`canContinue` из `src/games/recovery.ts` симулирует заданное число обычных действий ИИ и отвергает проигрыш; callback `won` отличает победу. Это короткая проверка продолжения, не доказательство бесконечной выживаемости. Проверка должна быть чистой и ограниченной по работе.

Текущие детали Session:

1. Сохраняет состояния до живых тиков в кольцевой истории. `steps` нормализуется до целого 1…240; хранится не более `min(steps*4,240)` состояний. Копий глубоко не создаёт — поэтому нужна неизменяемость.
2. Только при `state.over` проверяет `isLoss` (по умолчанию это `over`). Обычная потеря очка при `over=false` сама по себе спасение не запускает.
3. Выбирает состояние примерно на `steps` назад, затем более старые с интервалом около половины окна; не более десяти проверок. Кандидат должен быть живым и пройти `canResume`, если он задан.
4. Сразу выставляет режим auto и очищает ввод, но новые решения ИИ не выполняет до конца фазы. Движение/перехват на это время заблокированы; пауза замораживает фазу, R отменяет её.
5. Первую пятую `durationMs` показывает проигрыш, оставшееся время проходит по истории назад. На экране возвращаются реальные состояния, включая поле, фигуры, счёт и RNG. Частые idle-тики могут выглядеть одинаково; при единственном состоянии истории нескольких видимых шагов не будет.
6. После анимации удаляет отменённую ветку истории и продолжает ИИ с выбранного состояния. Seed и round не меняются. Цвет/мерцание задаёт renderer через `frame.recovery`; Tetris также скрывает ghost и вспышки рядов во время перемотки.
7. При отсутствии кандидата/истории или после двух спасений начинает новую auto-партию с `nextSeed(seed)` и round+1. Бюджет обновляется при новом ручном перехвате, restart и restore.

`durationMs` по умолчанию 320мс, минимум 1мс; не зависит от ½×/4×. Snake сейчас использует 8 шагов/640мс, Tetris — 24 шага/720мс. Браузер передаёт `animateRecovery=false` при prefers-reduced-motion: состояние неподвижно до финального перехода, цветовой сигнал без пульсации.

Во время восстановления `state` — текущий показываемый кадр истории, а `snapshot().state` — конечная безопасная точка. При невозможности спасения snapshot уже содержит новую живую партию со следующим seed/round. История не сохраняется в localStorage. После reload история пуста, пока не накоплены новые тики.

Для пошаговых игр (например, 2048) важно: Session записывает каждый живой тик, даже если `update(state,null)` вернул тот же объект. Ожидание человека может заполнить окно одинаковыми снимками и вытеснить предыдущие ходы. Параметр `steps` означает тики, а не совершённые ходы; одного возврата `state` без изменений недостаточно, чтобы пропустить запись. Для отката именно ходов нужна явно добавленная политика записи значимых переходов с тестом длительного ожидания. Сейчас такого hook в Game нет.

## Границы движка

Есть Canvas 2D, дискретное управление, фиксированные тики, seeded random, ручной/авто режимы, пауза, скорость, рестарт, bounded history/recovery и общая браузерная оболочка.

Нет встроенных ECS, сцены, объектов/спрайтов, камеры, физического мира, аудиоменеджера, сети, worker-поиска, asset loader, списка подключаемых ИИ или универсального UI настроек. При необходимости небольшую предметную механику реализует игра. Оценку столкновений, интерполяцию и несколько игроков нельзя считать готовым API.

Важно: текущая перемотка переключает снимки по тикам. Интерполяции положения Tetris между соседними снимками по пикселям пока нет; не описывай это как уже реализованную возможность.
