# Добавление картриджа и проверка результата

Содержание: файлы игры; регистрация; сохранения; настройки; оболочка/URL; проверки; автономная сборка.

Все пути относительно корня 0-player. Не внедряй примерную игру из этого руководства без запроса: выбирай механику по задаче пользователя.

## Структура и реальные образцы

| Файл | Содержимое |
| --- | --- |
| `src/games/<id>/game.ts` | Тип State, `create`, чистый `update`, предметные помощники и валидатор состояния |
| `ai.ts` | Действие из текущего состояния; ограниченный поиск, если он нужен |
| `render.ts` | Canvas-рисование и только визуальные эффекты |
| `index.ts` | `Game<State>`, метаданные, controls, metrics, recovery |
| `*.test.ts` | Правила, ИИ и взаимодействие с Session/сохранениями |
| `settings.ts` | Только если нужны параметры/стратегии: типы, нормализация, пресеты |

Для первого картриджа можно последовательно прочитать текущие `tetris/index.ts`, `tetris/game.ts`, `tetris/ai.ts`, `tetris/render.ts`. Snake показывает factory для разных параметров поля и стратегий. Дополнительные файлы вроде `pursuit.ts` или `clear-effect.ts` оправданы отдельной сложной задачей, а не обязательным шаблоном.

## Подключение: что уже общее и где есть привязки

| Место | Необходимое действие/ограничение |
| --- | --- |
| `src/catalog.ts` | Импортировать экспорт игры, добавить `cartridge(newGame)` в `catalog`. `cartridge()` создаёт Session и передаёт renderer состояние и frame |
| Порядок каталога | Пока сохранять Snake на позиции 0: `configureSnake()` и текущий `openSettings()` используют `catalog[0]`. Для перестановки сначала убрать эту привязку в пределах задачи |
| `src/storage.ts: validState` | Добавить ветку нового id с предметным валидатором. Неизвестные id сейчас всегда отклоняются |
| `src/main.ts: setGame` | Исправить подпись `screen-label` для новой игры: сейчас любая не-Snake подписывается «10 × 20», хотя Canvas масштабируется правильно |
| Иконка | В `main.ts` и `game-library.ts` есть Snake/Tetris и fallback gamepad. Для своей иконки обновить оба выбора и `icons.ts`; fallback уже рабочий |
| Подсказки | Метаданные controls подхватываются автоматически. Проверить общие тексты «Arrow keys take over» и кнопку ↑, если новая игра использует другую схему |
| Метрики | HUD ограничен первыми двумя; выбрать действительно полезные. Не рассчитывать на отображение остальных без изменения оболочки |
| Настройки | Сейчас кнопка/диалог доступны только Snake. Новый `settings.ts` сам по себе не создаёт UI и не добавляет контракт настроек в Game |
| Библиотека | Название, описание, поиск, карточка и цифровой выбор следуют каталогу. Цифры доступны только для первых девяти игр. При расширении проверить формат `GAME 0N` и поля с вводом цифр |

Не делай общий рефакторинг всего приложения только ради добавления одной игры. Если требуется универсальное поле подписи или валидатор в Game, меняй контракт явно, адаптируй существующие игры, тесты и этот справочник вместе.

## Сохранения и версии

`loadSession(id)` и `saveSession(id,snapshot)` работают через `0-player:save:<id>`. Объект сохранения имеет `version:1` и поля:

```ts
interface SessionSnapshot<S extends GameState> {
  state: S;
  mode: "auto" | "human";
  paused: boolean;
  speed: number;
  autoSpeed?: number;
  round: number;
  seed: number;
}
```

`speed` — фактическая скорость (у человека 1), `autoSpeed` — запомненная скорость ИИ. Старый снимок без autoSpeed восстанавливается через speed. Очередь, накопленные часы, визуальные эффекты и история в snapshot не входят. `Session.restore()` сам не валидирует внешние данные.

В текущем общем `validState` обязательны `score >= 0` (целое), boolean `over`, uint32 `rng`. Снимок проверяет mode, paused, допустимые speed/autoSpeed, round>=1, uint32 seed. Размер строки сохранения ограничен 200000 символами; неверный JSON/версия/инварианты дают null.

Валидатор игры должен проверять форму и диапазоны всех данных, которые дальше читают правила, AI и renderer: размеры, конечность чисел, клетки/фигуры, случайное состояние, фазы и согласованность полей. Для дробной физики используй `Number.isFinite` и предметные диапазоны, а не только integer helper. Терминальные позиции могут допускать столкновение, но живые должны удовлетворять правилам. Не ограничивай проверку одним TypeScript cast.

Новая игра может держать валидатор рядом с правилами, как `snake/game.ts: isSnakeState`; подключение в storage всё равно необходимо. При изменении формата существующей игры обеспечь безопасный отказ или явную миграцию; не меняй version без причины.

Оболочка сохраняет примерно раз в секунду, при переключении, скрытии и уходе со страницы. В памяти есть Map сессий для переключения при недоступном storage; после закрытия страницы этот fallback исчезает. Рекорды хранятся отдельно (`0-player:best:<id>`). Настройки — через `readPreference`/`writePreference` с префиксом `0-player:`.

При restore с явным seed сохранение загружается только при совпадении seed. У Snake дополнительно совпадают размеры поля. Для новой игры с несовместимыми настройками нужно добавить такую же проверку совместимости; не восстанавливай, например, старую доску на другой геометрии.

## Настройки игры

Game не имеет готового `settings` или `strategies` поля. По образцу Snake:

1. Типизировать и нормализовать опции; сохранять только проверенные значения.
2. Создавать `Game<State>` через factory с выбранными опциями.
3. Для смены стратегии на совместимом поле восстановить текущий snapshot в новой Session. Это сохраняет поле и параметры, но очищает историю и бюджет спасений. Для смены геометрии/несовместимых правил создать новую партию.
4. Хранить опции отдельно от session snapshot и проверять совместимость при загрузке.
5. Добавить UI и доступность кнопки в оболочке. React-root формы нужно размонтировать перед повторным созданием; диалог, пауза и применение опций принадлежат host.

Настройки используют установленные shadcn/Base UI компоненты в `src/components/ui` и semantic CSS из `ui.css`; дополнительные ставятся через `bun run ui:add @shadcn/<name>`. Основной Canvas/Session остаётся обычным TypeScript.

## URL и поведение оболочки

Пример ссылки: `?fullscreen=1&speed=2#game=tetris&seed=42`.

- Fragment: game id и seed. Query: fullscreen=1 для focus-layout, speed=0.5/1/2/4 для автопилота. Это не сериализация всей партии и не перенос localStorage другому человеку. Стратегия/размеры поля в URL сейчас не записываются: получатель использует свои preferences. Для ссылки на конкретные настройки нужно явно расширить URL-контракт.
- При первом открытии явный speed переопределяет сохранённую скорость; дальше игры сохраняют отдельные предпочтения. В ручном режиме URL продолжает хранить скорость ИИ, а человек играет на 1×.
- Focus из ссылки не запрашивает native fullscreen. Native fullscreen вызывается после жеста пользователя и может быть запрещён встроенным браузером; CSS-layout продолжает работать.
- Геометрия поля берётся из width/height картриджа; ResizeObserver подгоняет её под доступное пространство. Заголовок и dock не меняют высоту по таймеру. При перехвате в focus подсказки появляются в зарезервированной области.
- Игры не владеют URL и глобальными DOM-обработчиками: используйте существующие dispatch, setGame и диалоги.

## Проверки новой игры

Делай проверки поведения, а не копии реализации. Уместный минимум:

| Область | Сценарий |
| --- | --- |
| Правила | Границы, столкновения, счёт, старт/конец; входное состояние с замороженными вложенными данными не меняется |
| Воспроизводимость | Те же seed, опции, действия и mode дают тот же state; AI одинаков для оригинала и JSON-копии |
| ИИ | Длительная игра на нескольких seed; полезный прогресс вместо только «не упал». Для циклов проверить, что еда/цель действительно достигается |
| Перехват | Сначала AI, затем несколько ручных действий, A и продолжение без сброса поля/счёта/случайной последовательности |
| Темп | ½×/1×/2×/4× для AI, ручной 1×, возврат прежней скорости; режимы не задерживают управление |
| Сохранение | Корректная загрузка, испорченный JSON/данные, совместимость настроек, продолжение после reload и переключения игры |
| Восстановление | Реальный проигрыш, несколько исторических шагов, сохранение во время анимации, продолжение AI, pause, R, reduced motion, победа без ложного спасения; для пошаговой игры — длительное ожидание между ходами |
| Интерфейс | Библиотека, цифровой выбор, реальные key bindings, подсказки/touch, обычный и focus-layout, узкий экран |

Тесты Vitest с явными импортами `describe/it/expect`. Примеры интеграции: `src/engine/session.test.ts`, `engine/recovery.test.ts`, `games/recovery.test.ts`, `storage.test.ts`; дополнительные тесты игры лежат рядом с ней. В проекте нет настроенного Storybook или браузерного Vitest-проекта: не утверждай, что они уже есть.

Запускать из корня 0-player:

```sh
bun run test src/games/<id>/game.test.ts
bun run check
bun run build
bun run dev
bun run preview
```

`check` = oxlint + TypeScript + Vitest. `dev` — Vite-приложение; `preview` обслуживает последнюю production-сборку. После build уже открытая preview-вкладка сохраняет старый JS до reload. При изменении игры проверь именно свежую сборку и не сбрасывай пользовательские сохранения ради QA; используй отдельное тестовое origin/вкладку, когда нужно.

`vite.config.ts` встраивает JS, CSS и favicon в один `dist/index.html`, запрещает неожиданные split chunks/внешние артефакты. Используй статические импорты и встроенные/генерируемые ресурсы; не добавляй runtime CDN, обязательные шрифты/изображения с сервера или API-ключи. Для локальных bitmap-ресурсов явно обеспечь встраивание и проверь dist. Цель — автономное открытие и статический хостинг, включая GitHub Pages. Новую публикацию выполняй только по запросу пользователя.
