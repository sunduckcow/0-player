# Создание игр для 0-player

Создавай небольшие игры, которые играют сами, позволяют перехватить управление и продолжают сохранённую партию. Правила, ИИ и отрисовка — отдельные модули. Исходники модульные; результат сборки — один автономный HTML.

## Перед работой

Найди корень проекта по `package.json` и `src/engine/types.ts`; не полагайся на текущую рабочую папку. Прочитай [API движка](references/engine-api.md) и [интеграцию и проверку](references/integration.md). Источник истины — текущий код: сначала сверяй `types.ts`, `session.ts`, `catalog.ts`, `storage.ts` и используемые участки `main.ts`.

Для примера компактной игры изучи `src/games/tetris/index.ts`, для стратегии и размеров поля — `src/games/snake/index.ts`. При отличии кода от справочника используй установленный API и обнови затронутую документацию.

## Рабочий порядок

1. По запросу пользователя определи правила, что означает проигрыш/победа, счёт, управление и интересное поведение автопилота. Для непрерывной игры отдельно выбери: потеря очка завершает партию или только розыгрыш. Зафиксируй существенные предположения; уточняй только то, что нельзя разумно вывести из задачи.
2. Реализуй `src/games/<id>/game.ts`, `ai.ts`, `render.ts`, `index.ts`; дополнительные файлы добавляй по необходимости. `index.ts` собирает `Game<State>` с метаданными, размерами Canvas, `tickMs`, контролами и метриками.
3. Проверь правила на реальных состояниях: переходы, столкновения, границы, терминальные условия, неизменяемость и воспроизводимость. Добавь длительную симуляцию ИИ и проверку продолжения после действий человека.
4. Подключи игру через `cartridge()` в `src/catalog.ts`, валидатор состояния — в `src/storage.ts`. Пройди таблицу интеграции: одного добавления в каталог сейчас недостаточно для корректного восстановления и подписи поля.
5. Если игра поддерживает спасение, настрой `recovery` и визуальный ответ на `frame.recovery`. Проверь реальный проигрыш → историю назад → продолжение ИИ, включая сохранение во время отката.
6. Проверь переключение игр, клавиатуру/подсказки/touch, pause, takeover/A, R, скорость, URL, загрузку сохранения и focus на обычном и узком экране. Запусти `bun run check` и `bun run build`; итоговый `dist/` должен содержать один автономный `index.html`.

## Инварианты

- `update` и `ai` — чистые функции; состояние сериализуется в JSON. Вложенные массивы и объекты предыдущих состояний не изменяются: на них держатся история, поиск ИИ и сохранения.
- Вся случайность правил хранится в `state.rng` и проходит через `engine/random.ts`. Время и DOM не влияют на решения ИИ. Рисование читает состояние; визуальный кэш не определяет исход игры.
- ИИ возвращает обычный `Action | null`. Он соблюдает те же ограничения движения, что игрок, и умеет работать после ручного вмешательства и восстановления JSON.
- Человек играет на 1×; A возвращает прежнюю скорость ИИ без сброса поля и паузы. Пробел/P — пауза. Клавиши/подсказки/touch задаются в `Game.controls`; системные команды остаются за оболочкой.
- У движка дискретные действия: один тик — максимум одно действие. Удержание, отпускание, несколько одновременных кнопок и указатель не входят в контракт. Для Pong/шутера выбери явную дискретную схему либо согласованно расширь общий ввод; не обходи его скрытым обработчиком игры.
- Используй Bun и импорты `@/`. Canvas и правила не требуют React; shadcn/React нужны только для UI настроек. Для новых shadcn-компонентов используй `bun run ui:add @shadcn/<name>`.

## Когда работа завершена

Игра доступна в библиотеке, работает в обоих режимах, корректно сохраняется, не ломает существующие игры и автономную сборку. В отчёте укажи управление, поведение ИИ, поддержку восстановления, выполненные проверки и реальные ограничения. Новую игру или рефакторинг добавляй только в рамках запроса пользователя.
